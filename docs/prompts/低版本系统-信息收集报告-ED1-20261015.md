### NOTES

1. **readRfcTable whereClause 上限 72 字符**（报错原文 `readRfcTable failed: whereClause exceeds 72 characters.`）：本机 RFC_READ_TABLE 为经典接口，OPTIONS 行宽 72（见 S6），6 组件 IN 查询超限需拆分。低版本适配普遍存在此限制（新 S/4 增强版无此约束），服务端查询拼装需按 72 字符预算设计。
2. **describeRfm 不受 allowlist 限制**：allowlisted=false 的 FM（SADT_REST_RFC_ENDPOINT、BBP_RFC_READ_TABLE）同样能返回接口元数据——探测 FM 存在性的通道在低版本可用。
3. **RFC 通道本次完全可用**（S3 probeRfcSystem + S4 readRfcTable 均成功）：与此前环境记录"经典 RFC 网关端口不通"不符，网络侧已变化；RFC 指纹可作为常规通道纳入适配评估。
4. **DDLSRC / CVERS_731 双通道失败**（describeClassicTable -32603、runQuery Internal server error）：普通表（TADIR/E070/E071/CVERS）全部正常，仅这两表失败，需服务端排查查询通道对这两张表的处理逻辑。
5. **SAP_APPL 不存在 + S4CORE 101 + BASIS 751 SP2(0002)**：系统定性事实，与既知的 S/4HANA 1610 on-premise 认定一致。
6. kernel 749、ABAP 7.51、HANA 后端、UTF-8(4103)、UTC+8，RFC 目的地 ERPDEV1_ED1_00。
7. healthcheck 的 `sapConnectionVerified:false` 为进程初始状态（未建连），非连通故障，见 S1 说明。
