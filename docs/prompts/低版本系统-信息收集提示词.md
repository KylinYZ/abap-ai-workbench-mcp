# 提示词 2：低版本系统信息收集任务书（交给 AI agent 执行）

> 使用方式：前置条件——已完成《提示词 1》的接入且 `healthcheck` 成功。把本文件
> 全部内容交给接入后的 AI agent 执行。所有动作只读；每一步失败都要原样记录，
> **失败信息本身就是版本事实**，不要为凑成功改任何配置。

---

你是一台 **SAP 低版本系统（S/4HANA 1511/1610 或更老版本/ECC）** 上的信息收集
执行者。目标是为该 MCP 产品的低版本适配收集系统事实。你的输出是一份固定格式的
收集报告，逐节填写后完整回传。

## 铁律（违反即停止并报告）

1. **全程只读**：只允许调用下列清单中的只读工具。禁止调用任何名称含
   `apply`、`preview`、`create`、`delete`、`set`、`preview...Change`、`import`
   的工具；禁止执行 `INSERT/UPDATE/DELETE/DDL`。
2. `runQuery` / `readRfcTable` 只允许 SELECT 语义的读取。
3. 任何一步失败：把完整错误信息原样写入报告对应小节，然后继续下一步。
   **不要重试超过 1 次，不要绕过，不要修改连接配置或 profile。**
4. 不连接生产系统。如果 `healthcheck` 显示的连接目标与预期 DEV 系统不符，停止并报告。

## 收集步骤（按序执行）

工具名以你客户端里实际可见的 MCP 工具为准（profile 应为 development-workbench；
若某工具不可见，在报告该节写 `TOOL_NOT_VISIBLE` 并继续）。

### S1 服务器与会话状态
调用 `healthcheck`（无参数）。原样记录输出（重点：服务器版本、session、连接目标）。

### S2 ADT 通道系统身份
调用 `inspectSapSystem`（无参数）。原样记录输出（重点：系统身份、ADT 能力探测结果）。

### S3 RFC 通道指纹
调用 `probeRfcSystem`（无参数）。原样记录 `systemInfo` 全部字段
（sysid / release / kernel / host / codepage）。
失败则记录错误原文并标注 `RFC_CHANNEL_UNAVAILABLE`（不阻塞后续步骤）。

### S4 组件版本清单（区分 S/4 代次的关键证据）
用 `readRfcTable` 优先：`table=CVERS`，`fields=["COMPONENT","RELEASE"]`。
- 成功后，对 `SAP_BASIS`、`SAP_ABA`、`S4CORE`、`SAP_APPL`、`SAP_GWFND`、`SAP_UI`
  这几个组件，再用 `fields=["COMPONENT","RELEASE","EXTRELEASE"]` 补一次全列
  （若某列名不存在报错，回落到 `["COMPONENT","RELEASE"]` 并在报告注明列缺失）。
- `readRfcTable` 不可用时用 `runQuery`：
  `SELECT COMPONENT, RELEASE FROM CVERS`（禁止加不认识的列名）。
- 原样记录全部行。**特别注意 S4CORE 是否存在**：存在说明是 S/4（100=1511、
  101=1610），不存在说明可能是 ECC（看 SAP_APPL 版本）。

### S5 对象类型支持面（RAP 时代对象存在性）
用 `runQuery` 逐类型执行（一条一条，不要用 GROUP BY 以规避 datapreview 兼容缺陷）：
```
SELECT COUNT(*) AS CNT FROM TADIR WHERE PGMID = 'R3TR' AND OBJECT = 'BDEF'
SELECT COUNT(*) AS CNT FROM TADIR WHERE PGMID = 'R3TR' AND OBJECT = 'SRVD'
SELECT COUNT(*) AS CNT FROM TADIR WHERE PGMID = 'R3TR' AND OBJECT = 'DDLS'
SELECT COUNT(*) AS CNT FROM TADIR WHERE PGMID = 'R3TR' AND OBJECT = 'DCLS'
SELECT COUNT(*) AS CNT FROM TADIR WHERE PGMID = 'R3TR' AND OBJECT = 'STOB'
```
`runQuery` 不可用时用 `readRfcTable`：`table=TADIR`，`fields=["OBJECT"]`，
`whereClause="PGMID = 'R3TR' AND OBJECT = 'BDEF'"`，`maxRows=1`（有行=存在，
0 行=不存在；五个类型各一次）。记录每个类型的计数或错误原文。

### S6 关键函数模块存在性（第二传输栈与读表通道前置）
用 `describeRfm` 逐个探测（存在会返回接口描述；报错=不存在或非 remote，**报错
原文照记**）：
```
RFC_READ_TABLE / SADT_REST_RFC_ENDPOINT / RFC_SYSTEM_INFO / BBP_RFC_READ_TABLE
```
`describeRfm` 不可用时写 `TOOL_NOT_VISIBLE`（S3 的 probeRfcSystem 结果可部分替代
RFC_SYSTEM_INFO 的存在性）。

### S7 传输面可读性（受控链前置）
`describeClassicTable` 对 `E070` 和 `E071` 各调一次，记录列元数据是否返回成功。
再补一次 `runQuery`：`SELECT COUNT(*) AS CNT FROM E070`，记录计数。

### S8 版本敏感表存在性
`describeClassicTable` 对以下表逐个探测（返回成功=存在，报错=不存在，照记）：
```
DDLSRC（CDS DDL 源，7.40 SP05+）
DDLDEPENDENCY（CDS 依赖，7.40+）
CVERS_731（组件扩展表，7.31+）
```
若可见 `readClusterTable`，跳过（本步骤不需要）。

### S9 预检快照
调用 `sapDoctor`（无参数）。原样记录输出。

### S1 HEALTHCHECK
<原样输出或错误>

### S2 ADT_SYSTEM
<原样输出或错误>

### S3 RFC_FINGERPRINT
<原样 systemInfo JSON，或 RFC_CHANNEL_UNAVAILABLE + 错误原文>

### S6 FM_EXIST

### S7 TRANSPORT
E070=<describeClassicTable 结果摘要> ; E071=<...> ; E070_COUNT=<计数>

## 完成判据

S1-S9 全部有内容（成功输出或失败原文均算"有内容"）即为完成。
把报告全文回传给发起人。**不要**根据结果自行下"该系统能否适配"的结论——
定性由发起侧完成。
