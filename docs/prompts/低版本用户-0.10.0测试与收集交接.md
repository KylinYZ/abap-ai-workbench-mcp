# 交接说明：abap-ai-workbench-mcp 0.10.0 低版本（S/4 1511/1610）测试与信息收集

> 交给对象：在 S/4HANA 1511/1610（BASIS 7.50/7.51）DEV 系统上使用本 MCP 的用户。
> 使用方式：把本文件交给该用户的 AI agent（ZCode / Claude 等），按顺序执行。
> 全程只读红线：除步骤三的"拒绝验证"（预期失败的调用）外，禁止调用任何写类工具。

---

## 一、背景

`abap-ai-workbench-mcp@0.10.0` 是面向 S/4HANA 低版本（BASIS 7.50/7.51）的首个适配版本，
新增了三项低版本能力，需要在你的真实系统上验证：

1. **版本能力协商**：服务器连接后自动探测系统版本（RFC_SYSTEM_INFO 的 RFCSAPRL），
   据此自动隐藏/拒绝低版本不存在的工具（当前是 RAP 生成器面 11 个工具）与
   受控创建对象类型（RAP 时代 6 类）。高版本上行为完全不变。
2. **RFC 读表 72 字符兼容**：经典 RFC_READ_TABLE 的 OPTIONS 行宽 72，旧版上普通
   的长 IN 查询会直接报错；新版自动按安全边界切行，长查询照常工作。
3. **healthcheck 版本报文**：healthcheck 现在输出 `sapRelease` 段（生效版本、来源、
   被裁剪的工具与对象类型清单）。

## 二、安装/升级 0.10.0 并接入你的系统

```bash
# 升级（全局安装方式）
npm install -g abap-ai-workbench-mcp@0.10.0

# 或 MCP 客户端直接用 npx 固定版本（推荐）
# 客户端配置里的 args 改为：
#   ["-y", "abap-ai-workbench-mcp@0.10.0"]
```

MCP 客户端配置（把 `<尖括号>` 换成实际值）：

```json
{
  "mcpServers": {
    "sap-low-release": {
      "command": "npx",
      "args": ["-y", "abap-ai-workbench-mcp@0.10.0"],
      "env": {
        "SAP_URL": "https://<SAP主机>:<44300或8000>",
        "SAP_CLIENT": "<client>",
        "SAP_USER": "<用户>",
        "SAP_PASSWORD": "<密码>",
        "SAP_LANGUAGE": "EN",
        "SAP_MCP_SYSTEM_ROLE": "DEV",
        "SAP_MCP_TOOL_PROFILE": "development-workbench",
        "SAP_MCP_ALLOWED_HOSTS": "<SAP主机>",
        "SAP_MCP_ALLOWED_CLIENTS": "<client>",
        "SAP_MCP_ALLOWED_NAMESPACES": "Z,Y",
        "RFC_SYSNR": "<实例号两位，如 00>"
      }
    }
  }
}
```

配置后**完全重启 MCP 客户端**（新版本 + 新 healthcheck 会话生效）。
注意：**不要**设置 `SAP_MCP_BASIS_RELEASE`——本次要验证的正是自动探测。

## 三、验收测试（0.10.0 新能力的正向验证）

以下每步都记录原样输出。你的系统是 BASIS 7.50 或 7.51，下文以 751 为例
（750 的话 `CDS_METADATA_EXTENSION` 也应被裁剪，见 3.3）。

### 3.1 healthcheck 的 sapRelease 段
调用 `healthcheck`。**预期**：输出含 `sapRelease` 段，
`source: "rfc-probe"`、`basisRelease: 751`（或 750）。
若 `source: "unavailable"`：说明 RFC 通道不通（记录 healthcheck 全文回传，
这本身是有效结果——此时工具目录不会被裁剪，属预期的 fail-open）。

### 3.2 工具目录自动裁剪
让 agent 数一下当前可见的工具总数，并检查以下 11 个 RAP 工具是否**不存在**：
`rapGenValidateInitial` / `rapGenGetSchema` / `rapGenGetContent` / `rapGenGetUiConfig` /
`rapGenValidateContent` / `rapGenPreview` / `rapGenIsAvailable` / `rapGenGenerate` /
`rapGenPublishService` / `previewRapOperation` / `applyRapOperation`。
**预期**：11 个全部不可见；其他工具（readRfcTable、tableContents、searchObject 等）正常可见。

### 3.3 被裁剪对象的 dispatch 拒绝（双保留验证）
直接尝试调用 `rapGenPreview`（任意参数）。**预期**：返回错误且信息为
`Tool 'rapGenPreview' requires SAP_BASIS >= 755 but the target system reports BASIS 751.`
（750 系统同理，数字为 750。）

### 3.4 受控创建对象类型收窄
调用 `listRepositoryObjectCreationCapabilities`。**预期**：返回清单中**不存在**
以下 6 类：`SERVICE_DEFINITION` / `BEHAVIOR_DEFINITION` / `SERVICE_BINDING` /
`CDS_TYPE` / `CDS_ASPECT` / `CDS_ENTITY_BUFFER`；
`CDS_METADATA_EXTENSION`：751 系统**存在**、750 系统**不存在**。
再调 `describeRepositoryObjectCreation`（objectKind=`BEHAVIOR_DEFINITION`）。
**预期**：拒绝，信息含 `requires SAP_BASIS >= 755 ... reports BASIS 751`。

### 3.5 RFC 读表 72 字符兼容（旧版的已知失败点）
调用 `readRfcTable`：`table=CVERS`，`fields=["COMPONENT","RELEASE"]`，
`whereClause="COMPONENT IN ('SAP_BASIS', 'SAP_ABA', 'S4CORE', 'SAP_GWFND', 'SAP_UI', 'SAP_APPL')" `
（这条 WHERE 超过 72 字符，旧版必报 `whereClause exceeds 72 characters`）。
**预期**：0.10.0 正常返回行（S4CORE 有行=S/4；SAP_APPL 无行亦是有效信息）。

### 3.6 常规面回归抽查
`inspectSapSystem`、`searchObject`（query=`Z*`）、`tableContents`（表=TADIR，限 5 行）
各调一次，确认常规只读面正常（0.10.0 不应改变这些工具的行为）。

## 四、收集清单（适配定性所需，全部只读）

| # | 动作 | 要收集什么 | 为什么 |
|---|---|---|---|
| C1 | `healthcheck` 完整输出 | sapRelease 段原文 | 指纹链真值 |
| C2 | `inspectSapSystem` 完整输出 | ADT 能力探测结果 | ADT 面版本差异 |
| C3 | `checkAmdpDebugger` | 返回的可用性判定 | AMDP 调试资源面 7.51 真值（决定该面定性） |
| C4 | `checkInstallPrerequisites` | ZADT_VSP / abapGit 状态 | WebSocket 桥（git 导出）部署起点评估 |
| C5 | `readRfcTable` CVERS 全表（fields 仅 COMPONENT/RELEASE） | 全部组件行 | S/4 代次与 SP 级别核对 |
| C6 | `runQuery`：`SELECT COUNT(*) AS CNT FROM TADIR WHERE PGMID = 'R3TR' AND OBJECT = 'BDEF'`（再分别对 `SRVD`、`DDLS`、`DCLS` 各跑一次） | 各类型计数 | RAP/CDS 对象面真值复核 |
| C7 | `runQuery`：`SELECT COUNT(*) AS CNT FROM E070` | 计数 | 传输面可读性（受控链前置） |
| C8 | SICF 人工看一眼：`/default_host/sap/bc/apc` 节点是否存在、激活状态 | 存在/激活与否 | WebSocket 桥前置（SAP GUI 操作，agent 做不了） |
| C9 | 3.1 若 source=unavailable，把 healthcheck 的报错或 `[SapRelease]` 日志行抄下来 | RFC 通道失败原因 | 8 秒短超时的真实行为验证 |

> C6 的 runQuery 若报 `Internal server error` 或字段错误，原样记录——失败本身
> 就是版本事实（参考：某系统对 DDLSRC/CVERS_731 的查询双通道失败已留档）。

## 六、红线

- 只读：不调用 `apply*` / `preview*Change` / `create*` / `delete*` / `set*` 类工具；
  runQuery 只跑 SELECT。
- 不连接生产/QAS；凭据不写入回传内容。
- 测试中任何一步失败：原样记录后继续下一步，失败信息本身就是收集成果。
