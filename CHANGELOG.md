# Changelog

## [0.10.0] - 2026-10-16
- **S/4HANA low-release adaptation (BASIS 7.50/7.51, i.e. S/4HANA 1511/1610)** — release-capability negotiation, not capability rebuilding: the tool catalog stays identical on modern releases and trims automatically on older ones. Planning and the real-DEV (ED1 = S/4HANA 1610 SP2, BASIS 751 SP2, kernel 749, HANA) evidence baseline under `docs/S4低版本适配规划.md` / `docs/evidence/low-release-ed1-751-baseline.md`.
- **Release fingerprint + per-tool gating (M1)**: on startup the server lazily probes `RFC_SYSTEM_INFO` (RFCSAPRL, 8-second dedicated timeout so `tools/list` never crosses client protocol timeouts; failure disables the gate with zero behavior change — fail-closed against guessing). A deployment may also pin the release via the new `SAP_MCP_BASIS_RELEASE` env (highest priority). Gating is double-retained like the system-role gate: tools below their `minBasisRelease` are hidden from `tools/list` AND rejected on dispatch with an explicit version reason. Currently registered: the whole RAP generator surface (11 tools, min 755) and the AMDP debug kinds (min 753, kind-level — the generic ABAP debugger is unaffected). `healthcheck` now reports a `sapRelease` section (effective release, source `configured-env|rfc-probe|unresolved|unavailable`, trimmed-tool list).
- **RFC read-table 72-character OPTIONS compatibility (M1)**: classic `RFC_READ_TABLE` (7.51 and below) has a 72-char OPTIONS line width, which made ordinary long IN queries fail with `whereClause exceeds 72 characters` (real-machine confirmed). `readRfcTable` now splits long WHERE clauses into multiple OPTIONS TEXT lines at quote-aware space boundaries (the RFM concatenates them back; line order is the semantics). Quoted literals are never split; the only remaining rejection is a single unquoted token wider than 72.
- **Controlled creation kind trimming (M2-A)**: the 31-kind repository-creation catalog now carries `REPOSITORY_CREATION_KIND_MIN_RELEASE` — SERVICE_DEFINITION/BEHAVIOR_DEFINITION/SERVICE_BINDING/CDS_TYPE/CDS_ASPECT = 755 (RAP era; ED1 TADIR `BDEF=0/SRVD=0` real-machine), CDS_ENTITY_BUFFER = 757, CDS_METADATA_EXTENSION = 751 (absent only on 7.50); the other 24 kinds are release-unbounded. `listRepositoryObjectCreationCapabilities` trims, `describeRepositoryObjectCreation` and the preview path reject with an explicit version reason (plan state machine never entered); `healthcheck` reports `unavailableCreationKinds`. `apply` does not re-check (immutable-plan semantics: the preview-time verdict stands).
- Transport-precheck downgrade is confirmed pre-existing (M2-B, no new work): package/parent `transportchecks` calls were already softened (2026-09-29 ED1 round) with the request gate on a dual channel (ADT transportDetails -> E070 read-only SQL).
- Evidence note (2026-10-16): a false "ED1 reachable" assumption was caught and reverted before any write — real-machine actions must start with a connection-identity check (`healthcheck`/`inspectSapSystem`) against the expected host/sysid; see `docs/evidence/low-release-ed1-751-baseline.md` §7.
- Suite baseline 199/2244 (+56 across M0/M1/M2-A: fingerprint parsing, gating semantics, split algorithm, kind-matrix drift guards, handlers narrowing behavior).

- Add the deployment-level confirmation-mode switch `SAP_MCP_CONFIRMATION_MODE` (`native` default | `auto`): with `auto`, every controlled apply chain (source change, object creation, clone/rename, transport create/cleanup, activation, DDIC/package/RAP, quality check, debug, repository creation/cleanup) skips the manual native confirmation and executes in a single apply call. `auto` is honored only with `SAP_MCP_SYSTEM_ROLE=DEV` and fails closed at startup otherwise; it is driven exclusively by the deployment environment variable — callers cannot trigger it via any tool argument. Audit entries honestly record `confirmationMode=auto-config`; the plan state machine, drift/hash checks, and the audit chain are unchanged, and healthcheck echoes the active mode.
